13.1 错误码速查

所有 API 返回 Edge10Error，用 Edge10GetErrorString(err) 转字符串。

错误码 宏 含义 / 排查
0 EDGE10_SUCCESS 成功
100000 EDGE10_ERR_INVALID_PARAM 入参为 NULL / 尺寸不对 / enum 越界
100001 EDGE10_ERR_UNINITIALIZE 没调 Edge10Init 就用了
100002 EDGE10_ERR_REPEAT_INIT 重复 Edge10Init；一个进程只允许一次
100003 EDGE10_ERR_INVALID_FILE 模型文件打不开 / 不是 .ty
100013 EDGE10_ERR_PARSE_MODEL 模型损坏或与固件版本不匹配（见 VERSION_MATRIX.md）
100047 EDGE10_ERR_HOST_APL_TIMEOUT EP 侧 RPC 超时，查 PCIe 链路 / EP 进程是否起来
100052 EDGE10_ERR_RPC_TIMEOUT 同上，加重试或查 EP 负载
200000 EDGE10_ERR_BAD_ALLOC 设备显存不足；减小 batch / 分辨率
200002 EDGE10_ERR_INVALID_DEVICE device_id 不存在；先 Edge10GetRemoteDeviceCount
500004 EDGE10_ERR_DRV_FAILURE 驱动层错误，看 dmesg
500007 EDGE10_ERR_FILE_NOT_EXIST 路径不对
500008 EDGE10_ERR_FILE_PERM_DENIED 没权限；EP 包装器需要 root
600001 EDGE10_ERR_DEVICE_NOT_FOUND 没枚举到设备；跑 edge10-smi 看链路
600002 EDGE10_ERR_PCIE_LINK_DOWN PCIe 链路掉了；Edge10GetPcieLinkInfo 看 online
600003 EDGE10_ERR_EP_NOT_READY EP 侧 server 没起；跑 tyepctl start
600004 EDGE10_ERR_MODEL_MISMATCH 模型版本与 SDK / DEngine 不匹配
600005 EDGE10_ERR_VNET_NOT_ACTIVE 见下文“vnet 不激活”
600006 EDGE10_ERR_NOT_IMPLEMENTED 当前模式未实现
600007 EDGE10_ERR_BUF_EMPTY 非阻塞取帧时暂无数据（不是错误，正常分支）

13.2 vnet 数据面不激活（DEngine v1.17.0 已知问题）

影响：DE_RPC_CHN_SOCKET、DATA_COPY_NET 走 Socket / NET 通道时不通。

SDK 默认走 IPCM / PCIe-SHM，不受影响，业务代码不需要做任何事。

只有你自己要走 Socket 通道时才需要激活：

# EP 侧
ifconfig net_ipcm0 10.1.0.100 netmask 255.0.0.0 up
# Host 侧
ifconfig host_net_ipcm0 10.1.0.3 netmask 255.0.0.0 up

13.3 EP 程序一启动就报打不开 /dev/ipcm0

这是因为没走 mount namespace 包装器。不要直接执行 *_ep 二进制：

# 错误
./samples/bin/ep/flow_infer_ep model.ty

# 正确
edge10 --ep flow_infer_ep -m model.ty
# 或
Edge10-ep-run ./samples/bin/ep/flow_infer_ep model.ty

确认 /dev/host_ipcm0 和 /dev/host_notifier_userdev 存在；不存在就先：

sudo systemctl start edge10pcie-hostdrv
ls -l /dev/host_ipcm0 /dev/host_notifier_userdev

13.4 RC 二进制一启动就崩 / 走了 EP 初始化

说明环境里残留了 EDGE10_SDK_CONFIG 或 DEVPROP_INI。RC 进程必须在干净环境下跑：

env -i HOME=$HOME PATH=/usr/bin:/bin bash -lc '
    source /opt/edge10-sdk/env.sh
    edge10 --rc flow_infer_rc -m model.ty
'

或者直接用 edge10 --rc ...，它会在 run_rc() 里主动 unset 这两个变量。

13.5 VDEC 解不出帧 / 一直阻塞

  • 没调 Flush：短码流（如单张 JPEG、几帧测试片段）送完码流后必须调Edge10VdecFlush(dec)，驱动才会把缓存帧吐出来。
  • payload_type 不对：JPEG=26，H.264=96，H.265=265。
  • 宽高没传对：VDEC 需要在 create 时就知道最大分辨率，H.26x 序列里的SPS 与传入 width/height 不一致会直接失败。
  • 忘了 ReleaseFrame：连续取帧会很快耗尽内部帧池，后续 GetFrame*永远阻塞。

13.6 结果与离线模型对不上 / Top-5 偏了

  • 确认预处理与模型要求一致：输入尺寸、归一化、RGB/BGR 顺序、是否减均值。SDK 不做归一化，只负责把 NV12 → RGB planar 搬到 224x224。
  • 确认用的模型 .ty 与 VERSION_MATRIX.md 里的 DEngine 版本匹配。
  • EP 与 RC 结果应当逐位对齐；如果不一致，先确认两边加载的是同一个.ty 文件（EP 模式下模型要在 EP 文件系统上可见，或用文件传输接口传过去）。

13.7 性能上不去

  • 第一帧通常包含模型加载 / 图编译，做几次 warmup 再计时。
  • 推理路径上不要 H2D / D2H：用 ExecutorGetContext 让 VPC 直写输入，用 Infer(exec, NULL, out)。
  • 单进程多路用 InferAsync 把准备工作与推理重叠。
  • 想要满吞吐就上 --rc-ep 两进程，见 09_双卡并行。

13.8 日志

Edge10SetLogLevel(EDGE10_LOG_DEBUG);   /* 0=DEBUG 1=INFO 2=WARN 3=ERROR */

排障时把日志级别调到 DEBUG，能看到 DCL 调用细节。
